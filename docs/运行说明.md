# 多 Agent 出题工作流运行说明

## 环境要求

- Python 3.11 或更高版本
- Git
- `uv`
- DeepSeek Harness Python SDK
- `DEEPSEEK_API_KEY`

初始化本地环境：

```bash
cd /Users/azm/MyProject/exam-agents
uv sync --extra dev --extra deepseek
export DEEPSEEK_API_KEY=sk-your-key
```

Harness 使用标准 `sdk` profile。不得把 `sdk-minimal` 用于本流程，因为它不包含子 Agent，并固定使用 `danger-full-access`。

## 运行目录

每次运行只允许一个活跃题目：

```text
runs/<question_id>/
├── manifest.json
├── tasks/
├── reports/
├── gates/
├── logs/
├── homes/
└── worktrees/
```

`runs/` 已被 Git 忽略，不提交 session、日志或临时 worktree。

## 初始化

```bash
uv run exam-agents init-run \
  --runs-root runs \
  --question-id pet-exam-001 \
  --project-root /absolute/path/to/question-repo \
  --base-commit "$(git -C /absolute/path/to/question-repo rev-parse HEAD)"
```

查看状态：

```bash
uv run exam-agents status --runs-root runs --question-id pet-exam-001
```

## Agent 配置

| Agent | 配置 | 权限 |
| --- | --- | --- |
| coordinator | `agents/coordinator/config.json` | `read-only` |
| author | `agents/author/config.json` | `workspace-write` |
| material-reviewer | `agents/material-reviewer/config.json` | `read-only` |
| quality-reviewer | `agents/quality-reviewer/config.json` | `read-only` |

所有配置使用 DeepSeek Harness `sdk` profile。每个 Agent 使用 `runs/<question_id>/homes/<agent>/` 下的独立 Harness home。

## 分发与提交结果

```bash
uv run exam-agents dispatch-stage \
  --run-dir runs/pet-exam-001 \
  --agent author \
  --stage design \
  --instructions "完成并校验难度设计" \
  --required-file docs/reviews/难度设计检查.md

uv run exam-agents submit-result \
  --run-dir runs/pet-exam-001 \
  --expected-task-id task-design-abc123 \
  --result-file /absolute/path/to/result.json
```

结果必须符合 `schemas/result.schema.json`。reviewer 返回任何 `artifacts_written` 都会被拒绝。

DeepSeek Runner 会把完整的 `result.schema.json` 注入 Agent 消息，包括 required 字段、状态枚举、finding 结构和 classification 枚举。首次返回非 JSON、顶层不是 object 或不符合 Schema 时，Runner 会在同一 session 中要求 Agent 修正一次；第二次仍失败才中止。

## 真实多 Agent 运行

完成 API 配置后，从一个已提交的题目仓库启动真实流程：

```bash
uv run exam-agents run-real-workflow \
  --project-root /absolute/path/to/question-repo \
  --runs-root runs \
  --question-id pet-exam-001 \
  --agents-dir agents \
  --env-file .env \
  --approve-input
```

该命令会依次执行 coordinator 预检、author 设计与材料生成、两个只读 Agent 并行审查、输入冻结、答案生成和最终审查，最后停在 `HUMAN_REVIEW`。

不传 `--approve-input` 时，input 审查通过后会停在 `INPUT_REVIEW`，等待人工检查。

四个 Agent 均使用独立 Harness home 和独立 session。Runner 会把 `~/.codex` 注入为 `DSH_AGENTS_HOME`，使主笔和审查 Agent 能发现 `rubrics-growth-exam`。

最终发布必须另执行：

```bash
uv run exam-agents release-run \
  --project-root /absolute/path/to/question-repo \
  --runs-root runs \
  --question-id pet-exam-001 \
  --approve
```

## 输入冻结

材料审查通过并取得人工批准后冻结：

```bash
uv run exam-agents freeze-inputs \
  --runs-root runs \
  --question-id pet-exam-001 \
  --workspace runs/pet-exam-001/worktrees/author

uv run exam-agents verify-hashes \
  --runs-root runs \
  --question-id pet-exam-001 \
  --workspace runs/pet-exam-001/worktrees/author
```

冻结范围包括 `input/**/*`、题目说明、题目要求、难度设计和数据真实性设计。任何文件变化都会触发 `INPUT_INVALIDATED`。

## Worktree 与发布

- 主笔使用 `worktrees/author`。
- 审查 Agent 从最新 author draft commit 创建独立的 material-review 与 quality-review worktree。
- Harness Agent 不执行 Git 提交、tag、merge 或 push。
- 控制层负责提交 draft、冻结 tag、最终审批和发布。

## 当前边界

- DeepSeek Harness 是开发者预览版本，API 仍可能发生破坏性变更。
- 真实 API 运行必须在隔离虚拟机、容器或专用账户中进行。
- 默认离线测试不调用 DeepSeek API。
- 真实流程尚未用完整题目运行，只完成 API 冒烟、离线编排和配置装配验证。
- Web 管理界面、多题并发和自动业务裁决不在第一版范围。
